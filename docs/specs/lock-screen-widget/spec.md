# Spec: 잠금화면 뉴스레터 요약 위젯

> **무엇을 · 왜.** 잠금화면에서 오늘의 뉴스레터 상태를 빠르게 확인한다.
> Status: approved

## 배경 / 문제

사용자는 오늘 뉴스레터가 몇 개 도착했는지, 아직 읽지 않은 뉴스레터가 있는지를 확인하려면 앱을 열어야 한다. 잠금화면에서는 긴 기사 정보보다 현재 행동을 결정할 수 있는 숫자 요약이 더 유용하다.

## 목표 (Goals)

- 잠금화면에서 오늘 도착한 뉴스레터 수와 미읽음 수를 한눈에 보여준다.
- 원형 위젯에서는 미읽음 수를 가장 크게 보여준다.
- 직사각형 위젯에서는 오늘 전체 수와 미읽음 수를 함께 보여준다.
- 앱이 네트워크로 데이터를 가져온 뒤 App Group snapshot을 갱신한다.
- 위젯을 탭하면 Newdok 홈으로 이동한다.
- 로그아웃 뒤 이전 사용자의 숫자가 위젯에 남지 않는다.

## 비목표 (Non-goals)

- 위젯 확장 프로그램에서 서버 API를 직접 호출하지 않는다.
- 1차 구현에서는 기사 제목, 뉴스레터 이미지, 브랜드 목록을 표시하지 않는다.
- 홈화면 위젯, 인터랙티브 버튼, 위젯 설정 옵션은 다루지 않는다.
- WidgetKit의 업데이트 예산을 넘어서는 실시간 갱신을 보장하지 않는다.

## 유저 스토리

- 뉴스레터를 구독한 사용자로서 잠금화면에서 미읽음 수를 확인하여 앱을 열지 말지 빠르게 판단하고 싶다.
- 미읽음 뉴스레터가 있는 사용자로서 위젯을 탭해 Newdok 홈으로 바로 이동하고 싶다.

## 수용 조건 (Acceptance Criteria)

- [ ] 잠금화면 원형 위젯이 제공되고, 오늘의 미읽음 수를 숫자로 표시한다.
- [ ] 잠금화면 직사각형 위젯이 제공되고, 오늘 전체 수와 미읽음 수를 표시한다.
- [ ] 표시 데이터가 없으면 위젯이 크래시하지 않고 `0` 상태를 표시한다.
- [ ] 오늘 데이터 로드 성공 후 App Group snapshot에 전체 수·미읽음 수·기준 날짜가 저장된다.
- [ ] 오늘 기사 읽음 처리 후 미읽음 수가 갱신되고 위젯 타임라인이 reload된다.
- [ ] 과거 날짜의 기사를 읽어도 오늘 위젯 수가 잘못 변경되지 않는다.
- [ ] 자정 이후 전날 snapshot을 오늘 데이터처럼 표시하지 않는다.
- [ ] 로그아웃 또는 인증 상태 초기화 시 이전 사용자의 widget snapshot이 비워진다.
- [ ] 앱이 유효한 인증 토큰 없이 시작되면 이전 사용자의 widget snapshot이 비워진다.
- [ ] 위젯 탭 시 앱이 열리고 홈 탭을 표시한다.
- [ ] 서버가 아닌 App Group snapshot만 사용하며, snapshot 파싱 실패 시 빈 상태로 안전하게 동작한다.

## 열린 질문

- 없음. 1차 구현의 표시 값은 `오늘 전체 수`, `미읽음 수`로 확정한다.
