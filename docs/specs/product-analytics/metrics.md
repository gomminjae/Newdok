# Metrics: 사용자 행동과 이탈 분석

> Status: approved definition — definition_version = 1. 이벤트 계측은 로컬 구현 완료이며 GA4 보고서·정확한 원시 집계 연결은 아직 대기다.
> 이벤트는 [events.md](events.md), 제품 요구사항은 [spec.md](spec.md)를 따른다.

## 공통 집계

- u는 SDK 앱 인스턴스이며 원시 데이터의 stream_id + user_pseudo_id로 식별한다. 사람·계정·다른 기기를 합치지 않는다.
- s는 u + SDK ga_session_id다. 자체 세션 ID를 만들지 않는다. 식별자 누락은 해당 집계에서 제외하고 누락량을 보고한다.
- v는 article_view_id, n은 newsletter_view_id다. 인증은 auth_flow_id, 구독 화면은 subscription_attempt_id로 연결한다.
- 기준 시각 T, 신규 SDK first_open 시각 t0, 초기 계측 시작 T0를 기록한다. 구간은 시작 포함·끝 제외다.
- 검증된 상용 스트림·대상 버전/빌드만 포함하고 개발·테스트는 제외한다. SDK 자동 first_open에 app_build가 있다고 가정하지 않는다.
  최초 실행이 대상 버전인지 확인할 수 없으면 신규 코호트를 확정하지 않고 제외량·이유를 남긴다.
- 신규 코호트는 t0가 T0 이후인 대상이다. 이전 사용자의 첫 계측 이벤트를 신규 사용자로 바꾸지 않는다.
- 표시 시간대는 Asia/Seoul, 기간은 발생 시각 기준이다. GA4 속성 시간대와 차이가 있으면 명시한다.
- 분자도 같은 분모 집단이어야 한다. 비율에는 n/N·기간·정의 버전·수집 상태를 함께 표시한다.
- 분모 0은 해당 없음, 미계측은 미측정, 미성숙은 관찰 기간 미완료다. 0%로 바꾸지 않는다.
- BigQuery 최근 3일은 지연 이벤트가 반영되는 잠정값으로 관리한다. 관찰 기간과 데이터 준비를 함께 확인한다.
  [BigQuery 스키마](https://support.google.com/analytics/answer/7029846?hl=en)
- 기간 내 관측 지표와 관찰 완료 코호트를 구분한다. M04·M09는 노출·후속 행동 모두 선택 기간에 있는 같은 세션의 경로이며,
  기간 끝의 진행 중 세션은 잠정값이다. M02·M03·M05·M06·M08은 각 관찰 기간이 완료된 분모만 확정 집계한다.
  이미 성공했더라도 관찰 기간 미완료인 대상만 먼저 분자에 넣지 않는다.
- 원시 데이터의 사건 순서는 timestamp 단독 비교로 결정하지 않는다. 같은 timestamp가 가능하므로 실제 내보내기의
  event_bundle_sequence_id·batch_event_index 등 SDK 순서 정보의 가용성과 의미를 검증한다. 순서를 증명할 수 없는 건은
  엄격한 경로 집계에서 별도 미연결 건으로 보고하며 사건 이름으로 임의 정렬하지 않는다.
- SDK 발생 시각과 업로드/수신 시각·event_server_timestamp_offset을 실제 표본으로 대조한 뒤 기간용 시각을 확정한다.
  t0도 검증된 SDK 최초 실행 시각을 사용한다. 단순 수신 순서를 행동 시각으로 간주하지 않는다.
  이 확인 전 원시 집계는 구현·검증 대기이며 기존 GA4 개요와 같은 산식으로 표시하지 않는다.

## 화면·기능·뉴스레터 이용 보고서

M11·M12의 방문 u는 같은 대상 스트림·버전·기간에서 SDK session_start, E01, 아래 대표 기능 행동 중
하나가 관측된 u의 합집합이다. GA4의 참여 조건이 있는 활성 사용자와 임의로 같은 분모라고 가정하지 않는다.
화면·기능별 도달률은 중복 이용이 가능하므로 합계가 100%일 필요가 없다.
검색은 실행, 북마크·하이라이트는 성공, 읽기는 30초 도달로 사건 수준이 다르다. 보고서에는 이 기준을 이름에 표시하고
같은 수준의 시도율·성공률·기능 품질인 것처럼 순위를 해석하지 않는다. 공통 성공률이 필요하면 별도의 시도 분모가 필요하다.

| 기능 | M12의 대표 행동 | 의미와 한계 |
|---|---|---|
| 검색 | E14 | 유효 검색 실행. 이후 실패·취소도 검색 사용에는 포함 |
| 뉴스레터 선택 | E12 content_type=newsletter | 목록에서 상세를 열려는 선택. 노출 대비 CTR은 아님 |
| 기사 읽기 | E18 | 유효 열람 기준 충족. 단순 본문 진입과 구분 |
| 북마크 관리 | E27 added 또는 removed | 성공한 실제 상태 변경. M17 저장자 수는 added만 사용 |
| 하이라이트 적용 | E28 | 적용 저장 성공. 텍스트 선택·색상 편집·삭제만 한 사용까지 포괄하지 않음 |

| 날짜 탐색 | E24 action=change_date | 실제 다른 날짜 선택. 달력만 연 것은 제외 |

entry_point는 해당 화면·행동 흐름의 바로 이전 출처다. 뉴스레터 소개에서 기사를 열면 열람 출처는 newsletter_detail이며,
그 소개에 앞서 검색을 했다는 사실까지 같은 값으로 표현하지 않는다. 초기 보고서의 경로 열은 직전 진입 경로로 표시한다.
검색→소개→기사의 전체 발견 기여를 분석하려면 별도 연결 정의가 필요하며 이 값으로 추정하지 않는다.

화면 표시 횟수는 화면을 실제로 선택한 횟수나 가치의 크기와 같지 않다. 기본 홈 진입·프로그램 이동·뒤로 복귀도
화면 도달에 포함되므로 entry_point=launch 등 유입과 내부 이동을 분해한다. 기능 사용 여부는 위 행동으로 확인한다.
E01의 SDK 화면 이름이 원시 데이터에서 어떻게 정규화되는지는 실제 payload로 확인한다.
[Firebase 화면 측정](https://firebase.google.com/docs/analytics/screenviews)

뉴스레터 보고서는 stable newsletter_id를 그룹 키로 하고 공개 newsletter_name을 표시 보조값으로 사용한다.
같은 이름의 다른 ID는 별도이며 이름 변경도 같은 ID의 이력이다. 최신 공개 카탈로그 이름 매핑을 우선하고,
GA4에서 이름별 행이 갈라지면 ID 기준 수치를 사용해 원시 데이터에서 라벨을 정리한다.
표시명 누락은 ID로 남기며 실제 사용량을 버리지 않는다.

기사 수·발행 주기·추천 노출 차이 때문에 절대 열람량만으로 품질이나 선호를 단정하지 않는다.
짧은 기사는 실제로 다 읽어도 30초 미만일 수 있다. M14만으로 뉴스레터 사용량을 대표하지 않고 M18·M05와 함께 본다.
현재 E18의 임계점 값만으로 10초/20초 기준의 과거 코호트나 전체 열람 시간 분포를 재구성할 수는 없다.
현재 목록 단위 노출에는 개별 뉴스레터 카드 노출 분모가 없으므로 노출 대비 CTR·추천 공정성 지표를 만들지 않는다.
발행 기사 수로 보정하려면 기간 내 전체 발행 자료가 필요하며, 열람된 기사 수만을 분모로 대체하지 않는다.
현재 구독자 수·총 저장 보유량은 서버/저장 상태의 별도 근거가 필요하다. 앱 이벤트의 시도·추가를 그 수치로 바꾸지 않는다.

## 유효 열람

1. 현재 기사 본문의 메인 문서 표시 성공·로딩 가림막 해제 이후 시간을 센다.
2. scene 활성·기사 가시 상태에서만 단조 시계로 누적한다. 배경·다른 화면·본문 가림·로딩은 정지한다.
3. 같은 article_view_id에서 30초 도달 시 E18을 한 번 기록한다. active_visible_ms와 engagement_rule로 기준을 확인한다.
4. 재로드·하위 화면에서 뒤로 복귀는 조회 ID를 유지한다. 상세를 닫고 새로 열거나 계정이 바뀌면 새 조회다.
5. 초 단위 이벤트·강제 종료 직전 요약에 의존하지 않는다. 기준 도달 시 바로 기록한다.

30초는 초기 대리 지표이며 완독·이해를 증명하지 않는다. 전체 열람 시간도 이 임계점 값으로 계산하지 않는다.
기준 변경은 engagement_rule·지표 정의 버전을 갱신하고 지원 이벤트 버전·도입일을 기록한다.

## 정상 분기와 해석

- 기존 회원: 인증 시작 → login → 메인 표시.
- 신규 회원: signup_required → 프로필·약관 → sign_up → 가입 완료 안내.
- 계정 생성 이후: 추천 안내에서 skipped로 메인 또는 산업·관심사 저장 completed → 추천 → 메인.
- 게스트: guest_started → 허용된 탐색. 비로그인 자체를 이탈로 보지 않는다.
- 온보딩·가입의 각 단계는 E01 step_key로 측정한다. 정상 건너뛰기를 강제 단일 퍼널의 실패로 세지 않는다.
- 읽기 유지와 단순 재실행, 미복귀와 탈퇴·삭제를 구분한다. 발행 주기를 고려해 D1만으로 판단하지 않는다.
- GA4 코호트는 기기 기반이며 User-ID 계정 통합 코호트와 다르다. 시각 구간과 달력 코호트도 혼합하지 않는다.

## 확장 기준

새 지표는 ID·질문·결정·분자/분모·단위·기간·중복·필요 필드·제공 위치·기대값을 먼저 등록한다.
현재 데이터로 계산 가능하면 새 필드를 추가하지 않는다. 소규모 표본은 모수와 함께 보고 인과관계를 단정하지 않는다.
콘텐츠 ID별 열람은 발견·발행 여부와 함께 해석하며 선택 건수만으로 선호도를 단정하지 않는다.

초기 대시보드는 화면·기능 이용, 뉴스레터 이용, 이탈·유지의 세 영역으로 제공한다.
각 영역도 계측된 기능·기능별 수집 시작일만 표시한다. P1 전 검색·구독을 0으로 채워 전체 기능 순위를 만들지 않는다.
정확한 원시 집계가 없으면 GA4 개요와 상태를 표시하며 같은 이름의 근사값으로 대체하지 않는다.
