# Spec: 공통 선택 목록과 앱 시작 책임 분리

> Status: done — 2026-10-25 역할 분리·지연 로딩 구현. 후속 지시에 따라 공유 요청 관리 없이 단순 async 조회로 축소.

## 배경 / 문제

산업·관심사·요일 목록은 Auth·Explore·MyPage가 공유하지만 Explore가 조회를 소유한다.
앱 시작은 이 조회와 추가 1.5초를 기다리며, 실패하면 빈 목록으로 계속 진행한다.
회원가입 관심사는 별도의 하드코딩 목록을 사용한다.

## 목표 (Goals)

- 공통 목록의 조회·저장·준비 상태와 화면별 표현 책임을 분리한다.
- 필요한 화면에서 준비를 요청하고 성공한 목록을 재사용한다.
- 앱 시작은 로컬 세션 복원과 최초 화면 결정만 기다린다.

## 비목표 (Non-goals)

- 새 Core 모듈, 디스크 캐시, TTL, 범용 캐시 프레임워크 추가.
- actor 기반 요청 관리자, 진행 중 요청 병합, continuation·개별 대기자 관리.
- 로그인·온보딩·401 정책 변경, 서버 API 계약 변경, 배포.
- 홈 중복 조회 등 별도로 제안한 성능 개선.

## 유저 스토리

- 사용자는 홈과 무관한 선택 목록 조회를 기다리지 않고 앱에 진입한다.
- 선택 화면 사용자는 로딩·오류·정상 빈 목록을 구분하고 실패 후 재시도한다.
- 프로필 사용자는 목록 조회 실패를 프로필 미등록으로 오해하지 않는다.

## 수용 조건 (Acceptance Criteria)

- [x] AppRootView는 옵션 조회와 고정 대기 없이 세션을 복원하고, 복원 전 탭을 생성하지 않는다.
- [x] 공통 HTTP 조회는 App DI 경계에 있고 Shared에는 NetworkKit 의존성이 없다.
- [x] 저장소는 미조회·로딩·성공·실패를 구분하며 성공 결과를 재사용한다.
- [x] 화면의 .task 취소를 일반 async 조회에 전파하고 취소된 응답은 반영하지 않는다.
- [x] 실패 후 재시도 가능하며 잘못된 ID 중복·빈 이름은 부분 반영하지 않는다. 정상 빈 목록은 실패와 구분해 안내한다.
- [x] Auth·Explore·MyPage는 필요한 영역에서 로딩·오류·재시도를 표시하고 기존 선택을 보존한다.
- [x] 회원가입 산업·관심사는 동일한 서버 목록을 사용하며 미준비·무효 선택을 제출하지 않는다.
- [x] 단독 Example은 실제 네트워크 없이 옵션 fixture를 주입한다.
- [x] 실제 네트워크와 임의 sleep 없는 단위 테스트, 전체 테스트, Release 빌드 결과를 기록한다.

검증 범위와 Fastlane의 기존 경로 문제는 [tasks.md](tasks.md)에 기록한다. UI 수동 조작·실서버·실기기 성능 측정은 수행하지 않았다.

## 열린 질문

- `/options`의 공개 접근·401 계약은 별도 서버 확인 대상이다. 이번 변경에서는 기존 전역 401 정책을 유지한다.
- 1차 캐시는 기존과 같은 앱 프로세스 수명의 메모리 목록이며 서버 변경 반영 주기 확대는 후속 범위다.
